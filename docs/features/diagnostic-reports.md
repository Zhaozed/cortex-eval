# 评测归因报告模块：设计与实现

日期：2026-09-17。最新决策：**只保留一种归因报告；复用平台已有模型配置。** 本文替代早先“基础 / 归因两种报告 + Codex 接入”的草案。

## 1. 产品决策

| 问题 | 本次实现 |
| --- | --- |
| 报告类型 | 只有归因报告，不提供基础报告切换 |
| 模型 | 复用已有 LLM 配置，支持现有 OpenAI-compatible / Gemini 适配；不调用 Codex 桌面任务 |
| 入口 | 平台运行、离线导入运行详情页 → 生成归因报告 |
| Web 展示 | 运行内的大幅文档预览弹窗，不新增一级报告中心，不重复运行看板 |
| 交付 | 下载 Markdown；打开可离线阅读的 HTML，通过浏览器打印保存 PDF |
| 原始事实 | 平台计算并冻结；模型只增加诊断，不重判 PASS / FAIL，不重跑 Agent / Judge |
| 模型失败 | 同一份报告保留统计、断言和证据；显示归因失败，不偷偷切换报告类型 |
| 全通过 | 若无异常或非通过断言，直接整理报告，不调用模型 |

**只用一种报告是合理的；“给一个模型就能自动拿到 Agent 日志”是错误的。** 模型的归因上限取决于实际输入证据。本次只接入平台已保存的 Provider Output、断言、Case 和差异；未接入外部 Agent 日志 / 源码连接器。

## 2. 用户交互

1. 完整评测报告就绪后，点击「生成归因报告」。已有历史版本即使暂不能生成也能查看。
2. 选择平台已有模型。记住上次选择；否则优先使用本次运行的评测模型，再回退到列表首项。无需单独配置报告 Prompt。
3. 点击「生成报告」。界面明确提示：脱敏后的业务内容将发送给所选模型服务。
4. 后台整理事实并逐个分析待关注 Case，显示进度；可关闭弹窗或取消。关闭弹窗不取消任务。
5. 阅读报告，展开引用证据，跳回原 Case 执行链路；下载 Markdown 或打开打印版。
6. 重做分析使用「生成新版本」，不覆盖旧文档。历史版本保留当时的事实与模型配置 Hash。

首版不自动给研发发消息，不添加审批流程，也不宣称人工验收通过。

## 3. 文档结构

| 章节 | 内容 |
| --- | --- |
| 结论与范围 | 本次样本数、结果、待关注 Case 数、已完成诊断数；不生成无依据的发布结论 |
| 结果概览 | PASS / FAIL / 评测异常 / 未评测；执行异常独立统计；通过率、覆盖率明确分母 |
| 问题总表 | 每个待关注 Case 一行：原始判定、问题摘要、责任域、首查位置、归因状态 |
| 问题详情与归因 | 原始失败断言、现象、候选原因、证据引用、替代解释、修复方向、回归步骤 |
| 未覆盖项与限制 | 日志 / 源码未接入、摘录截断、版本未独立核验、人工复核未计入 |
| 全量 Case 索引 | 包括通过项；Run / 报告 ID、事实 Hash、模型配置 Hash、Prompt 版本 |

注意：PASS Case 中的质量告警也可以进入待关注清单，不因此将其重判为 FAIL。原有“产品行为 / 规则 / 标注 / 环境 / 待定位”分类继续保留，用于描述问题性质；新增结构化“责任域 / 首查位置”用于研发分流，同类现象不自动合并为同一根因。

### 3.1 具体归因模块

每个完成归因的 Case 都必须给出以下四项：

| 字段 | 可选值 | 用途 |
| --- | --- | --- |
| 责任域 | ToolHub、Agent、A2UI、框架运行时、评测规则 / 测试数据、环境 / 配置、暂无法定位 | 判断应该先由哪类研发负责人接手 |
| 首查位置 | Planner 提示词、Router 提示词、ToolHub 契约 / Schema、ToolHub 工具实现、Agent 编排逻辑、A2UI 出站 Payload、A2UI 渲染 / 展示、评测框架运行时、断言规则、Case / 测试数据、环境 / 部署配置、暂无法定位 | 给出第一排查点，而不是泛泛写“检查 Agent” |
| 定位信心 | 高 / 中 / 低 | 表示对排查方向的信心，不表示根因已证实 |
| 定位依据 | 一段结构化说明 | 解释为何把该问题分到这个模块，并引用可见事实 |

定位规则：没有 Planner / Router 的实际 Prompt 或 Trace 证据时，不允许把问题确定归因到 Planner 提示词或 Router 提示词；只有看到“有出站 Payload 但展示失败”才能优先指向 A2UI 渲染，否则要区分 A2UI 出站 Payload、Agent 编排和框架采集问题。平台只校验枚举和证据 ID，不会把模型的分类自动当成已确认根因。

## 4. 归因可信边界

| 标签 | 含义 |
| --- | --- |
| 证据支持（AI 判断，待人工核验） | 模型认为可见证据支持原因，不等于已确认根因 |
| 推测待验证 | 有现象与候选解释，尚缺验证 |
| 证据不足 | 缺少支持判断的证据，需补充采集 |

平台校验证据 ID 是否真实存在；拒绝虚构引用。无引用强制标为证据不足；不足两个引用或没有引用未截断的执行输出时，不接受“证据支持”状态。**这些只是结构性约束，不是因果正确性的自动证明。**

任意自定义 JS 规则若未提供结构化解释，保留原始失败事实，不承诺自动证明该规则的语义。Agent 自报卡片输出不等于浏览器展示验证。配置中声明的分支 / commit 不等于部署版本已核验。

## 5. 实现概要

- 新增独立归因报告 API、持久化任务和模型适配，不复用会生成断言修改建议的既有 Case Analysis。
- 报告 Prompt 升级为 `diagnostic-report.v2`：模型必须输出 `attribution.domain / location / confidence / rationale`；服务端兼容读取 `v1` 历史报告。
- 任务状态：整理事实 → 归因中 → 已生成 / 部分失败 / 失败 / 已取消。
- 同一运行的相同模型重复请求复用活动任务；不同模型冲突时拒绝。最多三个运行同时归因，每个运行按 Case 顺序处理，不自动重试付费请求。
- 侧文件存储于项目 `.cortex-eval/diagnostic-reports/`，原子写入；进程重启保留已完成事实，标记未完成任务中断，不自动恢复模型调用。
- 凭据按字段、常见 token 模式和运行环境中的已知密钥脱敏；业务正文仍可能敏感，分享前需要人工检查。
- 模型不获工具执行权限；输入按不可信数据处理；Web 按类型渲染文本；HTML 不执行模型提供的脚本。
- 原始评测完成 / 取消状态与归因任务相互独立。
