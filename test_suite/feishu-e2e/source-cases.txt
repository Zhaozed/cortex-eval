3. 通用需求
- 工具聚合后，独立测试 Prompt 明确“飞书”来源；多轮可复用已经确认的飞书来源和资源 ID，不误切 Slack、Google 或 Outlook。
- 以当前用户连接和授权执行；未连接、权限不足、资源不可见与空结果分开说明。恢复授权后核对原对象，不盲目重复写入。
- 对象唯一则直接继续；同名、多人、多日历或指代不唯一时展示可信候选或普通文本澄清。保留 provider、原始 ID 和可信 URL。
- 时间按用户时区解析；有完整日期、起止和人员时不重复询问；缺少执行必要信息或遇到冲突才澄清。
- feishu_send_message 与 delete_events 使用一次最终危险确认；修改目标/正文后更新待确认内容。当前分支没有文档写入或日程创建/更新的同类危险确认卡，关键预览使用普通文本。
- 写后用真实返回 ID 回读；区分接口成功、资源存在、正文正确、邀请接受、房间占用和收件人已读。回读是本篇验收要求，不宣称存在强制自动保障。
- 分页、限额、截断与部分失败可见。成功部分保留，失败部分说明；超时/未知先只读核对，避免重复发信、新建、追加或删除。
- “好了吗”“没看到”“确认一下”本身不授权新写入；不能操作同名对象制造表面成功。

5.1 D01 搜索并选择飞书文档（读取 / 同名消歧）
1. 背景与目标
- 场景：用户记得文档关键词，需要定位正确方案。
- 目标：选中真实文档并保留其身份供后续读取。
2. 触发条件
已连接飞书；有关键词或所有者线索，尚无唯一文档链接。
3. 用户的话
“帮我在飞书找一下《发布方案》，我要产品组那份。”
4. Agent 期望链路
1. 调用 feishu_search_docs(query, doc_types=docx)，按 offset 获取所需结果；不传 page_token。
2. 比较标题、类型、可信 URL 与所有者；需要且接口可用时用 feishu_get_user_profile(target_user_id) 核对所有者。
3. 唯一命中直接读取；多个候选交用户选择；成功空结果说明未找到，权限失败说明真实原因。
5. UI 期望响应链路
搜索结果 list_simple → 多候选沿旧卡选择，唯一命中直接继续 → 读取选中文档正文 markdown_title_body
1. 【Agent】按标题/所有者定位
2. 【A2UI】读取中；tool_start · started/default
3. 【A2UI】读取结果；list_simple · default
4. 【无新卡】多候选沿原卡选择；唯一命中直接继续
5. 【A2UI】读取选中文档中；tool_start · started/default
6. 【A2UI】选中文档正文；markdown_title_body · default
异常分支：【A2UI】tool_fail 仅在真实调用失败时出现；【文本】说明失败原因、已完成项和未执行项。前置依赖失败停止依赖写入，未知结果先回查。
暂时无法在飞书文档外展示此内容
6. 验收关注点
- 同名未选定前不修改文档；缺失 owner 姓名不以内部 ID 充当人名；分页未结束不声称搜遍全部。
- 证据与待验证边界：资料记录搜索可用；指定用户资料反查效果仍需真实验证。
5.2 D02 按链接阅读、总结与问答（读取 / 内容理解）
1. 背景与目标
- 场景：用户提供飞书 Docx 或 Wiki 链接，需要理解正文。
- 目标：依据实际读取内容回答并保留来源。
2. 触发条件
有用户提供或已选中的真实 doc 链接；当前用户有阅读权限。
3. 用户的话
“帮我读一下这份飞书文档，概括决策、风险和待办。（附文档链接）”
4. Agent 期望链路
1. 沿提供的 doc 调用 feishu_get_doc；Wiki 按接口解析结果继续，不重新按同名搜索。
2. 核对正文是否完整，提取决策、风险、待办；原文未写的推断要标明。
3. 返回标题、真实链接和基于正文的结论；读取不全时说明仅覆盖已读部分。
5. UI 期望响应链路
真实文档正文和来源；总结使用普通文本
1. 【Agent】沿用户提供的链接读取
2. 【A2UI】读取中；tool_start · started/default
3. 【A2UI】读取结果；markdown_title_body · default
4. 【文本】基于已读正文总结并附来源
异常分支：【A2UI】tool_fail 仅在真实调用失败时出现；【文本】说明失败原因、已完成项和未执行项。前置依赖失败即停止依赖写入；未知结果先回查。
暂时无法在飞书文档外展示此内容
6. 验收关注点
- 空正文不以标题生成总结；无权限与空文档区分；Wiki、长文单独验收。
- 证据与待验证边界：普通 Docx 有受控样本；Wiki、长文全量未验证。

1. 背景与目标
- 场景：用户已取得资料，希望整理成可交付文档。
- 目标：使用确定的来源版本创建文档并核对正文。
2. 触发条件
来源内容可恢复；有标题或授权 Agent 拟题；存放位置可执行。
3. 用户的话

4. Agent 期望链路

3. 调用 feishu_create_doc；用返回的 document_id 调用 feishu_get_doc 核对标题与正文，再交付 URL。
5. UI 期望响应链路
写入状态后读取新文档，展示核对过的正文和链接

2. 【文本】必要时核对标题与正文
3. 【A2UI】执行中；tool_start · started/default
4. 【Agent】按真实 document_id 回读核对；缺正文不伪造成功卡
5. 【A2UI】真实结果；markdown_title_body · default
6. 【文本】核对标题、正文与稳定链接
异常分支：【A2UI】tool_fail 仅在真实调用失败时出现；【文本】说明失败原因、已完成项和未执行项。前置依赖失败即停止依赖写入；未知结果先回查。

- 证据与待验证边界：创建有样本；跨任务来源复用与稳定自动回读需实测。

2. 触发条件
