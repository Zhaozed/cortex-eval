# Todo 分层回归使用说明

## 范围

| 层次 | 当前检查 | 不代表什么 |
| --- | --- | --- |
| Planner 36例 | 工具选择、参数、提问、来源/默认状态、禁止写入/重复写规划、防泄露 | 不代表工具实际执行或任务完成 |
| E2E 8例草稿 | 实际调用、关联终态、指定返回字段、数量/集合、时刻、回复交付；独立回复语义评分 | 尚未真实执行、语义评分未真实验证，不代表视觉验收 |
| A2UI固定模板 | 复用既有 Web 截图和逐Case人工审核 | 不代表本次真实Agent输出截图、iOS验收 |

**自动失败不能被人工通过覆盖；截图生成、REST成功、轨迹可消费都不是业务通过。**

## Planner生成和使用

```sh
pnpm todo:prepare --input <现有Planner源JSONL> --output <全新目录>
```

生成修正后的 `planner.cases.jsonl` 和独立的 `e2e.draft.cases.jsonl`。只写新目录，不覆盖源、不调用服务、不自动导入、不发起运行。已有目录拒绝写入。生成器只适用于这批 Todo Planner Case，不是任意JSON Schema迁移器。

Planner运行必须选择 `/run_llm_task/planner`，请求体 JSON Pointer 为 `/request_body`，Provider输出保留完整 `{ok, task_name, parsed_output}` 信封。E2E入口 `/eval/e2e` 不能用于Planner集；误用会在评测阶段被新增口径断言判失败，但这是事后检查，不是执行前安全门禁，不能阻止误接E2E产生副作用。`time/timezone` 是直跑Planner的显式时间输入，不要机械用于E2E生产时钟。

修正依据是当前Cortex契约：普通Task查询默认未完成，Task来源不自动混入iOS Reminder；S02原输入为“看看我的待办”，不是“所有状态”。在线工具的 `user_id` 在Planner输出格式化时剥离，由执行边界按权威身份注入，所以Planner Case检查其不出现，不要求模型生成身份；账号归属需在E2E请求身份/执行证据层验收。

旧阻断断言不再用 `weight=0`，本批统一正权重、threshold=1。对目标投影补必填，字符串pattern补类型；单目标/单批次写规划最多一次。提问/说明必须有非空正文；纯工具Planner回合允许显式 `reply_text=null`。没有添加自由文本解释语义评分的Planner Case，只证明结构/正文存在，不证明解释正确。

## E2E草稿绑定清单

**草稿的 `uid=0` 故意非法，当前Cortex请求契约会在入队前拒绝它。不得直接运行或把这次拒绝计为业务验收。** 该限制只适用于当前Cortex契约，不是对任意自定义Endpoint的通用安全机制。请求不传模拟tools/task_history/time，不拿这些字段伪造授权、历史或系统时间。

| Case | 需要准备的真实前置条件 |
| --- | --- |
| 01 正常查询 | 专属已授权ToDo账号，查询精确返回一条已知事项 |
| 02 空结果 | 专属账号，确实没有未完成事项；工具成功空集合才是空结果 |
| 03 创建 | 经确认的可写账号/清单、唯一运行标记；记录实际返回ID |
| 04 信息不足 | 已授权且目标平台明确，缺标题时只澄清、不提前写入 |
| 05 授权不足 | 经人工确认的真实无授权账号，不靠Case模拟授权 |
| 06 工具失败 | 隔离环境的受控故障，不通过破坏共享服务制造超时 |
| 07 时区跨日 | 明确日期和Asia/Shanghai时区，核对返回时刻而非只看调用参数 |
| 08 多条结果 | 两条已知事项，无序精确集合；排序/分组不在本条验收范围 |

绑定前由负责人确认账号、授权、可写范围与副作用。替换草稿uid、虚构资源ID、完整golden记录、日期和唯一标记，同时修改对应预期，记录业务依据。修改预期不能仅以实际输出为依据。

固定日期只是输入，不是冻结真实E2E时钟。需分别保存请求中可识别的时间、trace实际接收/采用时间；相对日期在生产时钟规则确认前不写虚假的确定预期。

查询集合比较是**完整记录、无序、数量精确、拒绝重复相同记录**；实际返回新增字段也会失败，须按正式工具契约准备完整golden，不删除字段迁就输出。需要顺序时用 `fields` 数组精确比较。时间字段必须带时区，按同一时刻比较UTC和偏移表示。ToDo截止时间的精度/归一化存在待确认差异，不改成只比日期以掩盖它。

执行断言有意限定为本批单调用工具请求：每个执行恰一call、一terminal，按tool_request_id关联，拒绝额外/重复执行，成功返回的嵌套provider_errors/account_errors必须为空数组或不存在。复合工具、多终态恢复链不在此样板覆盖内，不能直接套用。

终局回复检查使用trace的 `request_identity.root_req_id`，关联 `final_output` 和 `delivered_messages` 的请求、消息ID、类型与正文，不能用旧过渡消息证明新终局回复已交付。独立 `llm-rubric` 检查回复与工具事实是否一致；模型评分不是客观事实源，也不是视觉判断。接入平台时需配置可用Evaluator，并在首次真实评分时确认其能读取完整预置ProviderOutput；本轮没有模型评分结果。

## 数据隔离和清理

1. 只在专属测试账号/明确清单运行；先只读核对golden及授权，不通过线上写入猜测权限。
2. 写入标题使用唯一 `[EVAL:<run>:<case>]` 标记，保存返回资源ID、provider、账号和Run/Case对应记录；静态 `[EVAL-SAMPLE]` 不是正式运行标记。
3. 仅清理本Run记录的准确资源ID，清理前核对账号和标记；禁止按标题模糊批量删除，禁止清空整个账号。
4. 本批共享查询条件覆盖同一账号的全部open事项，因此查询/创建/空结果互相影响，默认串行，写入后清理并复核再运行其他Case。稳定只读集只有在数据隔离得到证明后才并发。
5. 不要求每次写入都读回；当返回不足以证明持久化或存在归一化疑点时，对关键场景按实际资源ID独立查询，保留差异。

## A2UI证据边界

当前 `a2ui=[]` 也可能表示采集失败，不能证明“确实无卡”。E2E草稿不包含虚假的无卡断言；无卡/真实卡内容验收在补足可区分的采集证据前均标未验证。不要用 `present_mode` 或固定模板截图替代真实出站证据。

已有6例固定Web回放、7张图及审批记录只作为历史归档，不再新增固定回归或审批，不列为必跑项。真实A2UI验收随E2E Case组织；目前真实截图采集与绑定尚未实现，不能将历史截图当作本次结果。产品模板库不变；不新增独立审核模块、AI视觉、像素diff、按钮交互或iOS自动化。

## 失败处理

保留具体断言reason，归因为产品缺陷、Case/预期错误、环境/数据问题、评测工具问题或证据不足待确认。超时不是空集合，规划成功不是执行成功，历史报告不能通过修改当前Case追溯“改绿”。总回归先按功能/层次登记必跑清单，不新增跨测试集调度引擎。
