## 验收组成与明确缺口

| 检查 | 实现/边界 |
| --- | --- |
| 实际执行 | 要求实际调用、关联唯一终态、成功结果；拒绝缺证据、串平台、provider/account 部分错误 |
| 关键参数 | 创建数量、标题/优先级/备注、指定清单ID存在；修改任务ID和新字段；删除单个明确ID |
| 禁止/重复写入 | 使用共享规则，按真实工具名 create_tasks / update_task / delete_tasks 配置；不靠名称猜任意工具副作用 |
| 业务结果/回复 | 每例独立 llm-rubric 核对实际返回、身份、相对日期与最终交付；不是所有返回字段都已经确定性断言化 |
| 时间/资源可信依据 | 仍需真实账号、清单/任务ID基线与运行时间；不根据错误输出倒改预期；产品原生平台核对不能由Judge冒充 |
| A2UI | 这些原始场景均要求展示走查，开启现有复核选项；动态渲染并由人审核，不做视觉评分 |
| 多轮整例证据 | **9例显式评测阻断**：CU/TD-03、06、07、08，MX-03。现有末轮证据不能证明中间取消、创建、完成行为及中间卡片 |
| 尚未定义规则 | MX-01“最近”时间窗口；MX-04遇到时分“降级保存”还是“先澄清”。显式评测阻断，不能任选宽松口径。CU/TD-03同样需要最近窗口，本身也受多轮阻断 |

上述阻断通过明确抛出 `EVIDENCE_INSUFFICIENT` / `ACCEPTANCE_RULE_UNDEFINED` 暴露评测缺口，不判为 Agent 产品缺陷。它们**不是执行前安全拦截**：一旦绑定真实账号并发起运行，工具仍可能执行。补齐证据/确定规则后必须替换对应阻断断言，不能只隐藏错误或设 weight=0。

全部断言正权重、整例 threshold=1；Judge 通过或人工通过不能覆盖确定性失败。字段有值/接口成功不等于任务完成。没有完整多轮证据前，不宣称整例已经自动验收。
